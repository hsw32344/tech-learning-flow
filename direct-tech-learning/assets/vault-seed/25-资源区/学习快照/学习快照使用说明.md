# 学习快照使用说明

学习快照是每个任务包一份的累计教学产出，用于跨会话续接、查漏和复习路由。它适用于 FCC、普通教程、官方文档、实体书、本地材料和明确登记的 Agent fallback，不绑定某一种课程结构。

## 是什么 / 不是什么

- 是：来源定位、应掌握地图、已覆盖源内容、机制级讲解、应用例子、边界、岗位映射、停止位置和遗留项的累计归档。
- 不是：用户学习活动、任务完成、掌握程度、能力证明或主线进度。
- 不是：用户 Notebook 的替代品；不得复制或覆盖用户笔记。
- 机器校验通过只证明结构满足合同，不能证明解释忠实、技术事实正确或用户已掌握。

## 存放、命名与写权限

- 路径：`25-资源区/学习快照/<任务包 ID> 学习快照.md`。
- 每个任务包只有一份，原地累计更新，不建立日期副本。
- `study-tech-learning` 是唯一写入者；快照不会触发 `record-tech-learning`。
- 其他笔记引用快照使用相对 Markdown 链接，避免附件式目录造成双链校验问题。

## 资料线与学习线

- 资料线：新来源包达到 `verified`，完整覆盖目标切片，并通过写入前的完整性、因果链和明显技术冲突筛查后，`study-tech-learning` 立即写入或更新快照，再运行 `validate-snapshot.ps1`。
- 学习线：用户随后是否阅读、提问、练习或完成该切片，按实际活动单独推进；快照存在不推进学习进度。
- 只准备快照时，可以在快照校验通过后结束，不生成学习完成或掌握记录。
- 同一请求包含学习时，先完成资料线，再从已验证的快照切片开始讲解。已有合格缓存无需重复写入，除非内容被纠正或扩展。
- 写入前筛查和结构校验都是有限检查，不能单独证明技术内容完全正确。

## 对话渲染边界

- 快照按切片把 `主源内容`、机制、规则、例子、边界和记忆/理解保存在一起，是为了累计存储和缓存复用；它不是 `study-tech-learning` 的对话模板。
- 对话输出只服从插件 `references/study-session-protocol.md`：先完整输出“主源忠实讲解”，再输出与其逐项对应的“结构化知识点”，不得合并或交错。
- 复用快照缓存时，先把目标行和对应切片正规化为来源条目、源内例子/核验、机制、规则、应用与预期结果、边界、记忆与理解，再按对话模板渲染；不得直接模仿快照 Markdown 分组。
- `contract: mixed-v2` 只描述历史切片的存储兼容性，不允许改变当前对话阶段、标题、来源标签或字段完整性。

## 已核验快照缓存

学习快照可以作为跨会话复用的已核验教学缓存，但仍不是用户学习活动、任务完成、掌握程度、能力证明或当前来源新鲜度证明。

frontmatter 必须包含：

- `source_packet_status`：`verified`、`agent-fallback`、`partial` 或 `blocked`；
- `source_verified_at`：`verified` 使用实际核验日期 `YYYY-MM-DD`，`agent-fallback` 使用 `无/不适用`，`partial` 或 `blocked` 使用已知核验日期或 `未知/待核验`。

目标切片同时满足以下条件时，`study-tech-learning` 和 `load-tech-learning-source` 可以直接复用，不重新获取同一来源：

1. 快照通过 `scripts/validate-snapshot.ps1`；
2. `unit` 和 `primary_source` 与当前任务解析结果一致；
3. `source_packet_status` 为 `verified`，或为主线明确登记范围内的 `agent-fallback`；
4. “已覆盖切片”和“结构化知识点”中存在相互对应的目标切片；
5. 目标切片具备主源内容、机制、底层规则、应用例子、边界/错误、记忆与理解及源内核验；
6. 遗留问题没有声明该目标切片的来源失效；
7. 当前请求不要求逐字核对原文、重新验证版本或解决来源冲突。

使用缓存时必须保留原始 locator、来源核验日期和来源标签。`[主源原文]` 表示来源忠实内容，不自动表示逐字全文；Agent 补充仍使用 `[理解补充]` 或 `[应用映射]`。源内交互为“待用户完成”不会使缓存失效。

只有目标切片缺失、结构校验失败、状态为 `partial`/`blocked`、主源登记改变、出现版本冲突、遗留问题使目标切片失效，或用户要求逐字核验时，才加载最小必要的来源正文。

## 通用来源定位

必填字段为任务包、主源、来源角色、actual_locator 和源锚点。不同来源按实际结构记录：

| 来源 | `actual_locator` / 源内容单元示例 |
|---|---|
| FCC | superblock、block、challenge-id、仓库路径 |
| 普通教程或官方文档 | URL、页面标题、章节/小节/API、版本 |
| 实体书 | 书名、版本、章/节/页码（未知项写待核验） |
| 本地文件或 Notebook | 绝对路径、标题、行号或 cell 标识 |
| Agent fallback | 原因、限定范围、未覆盖边界；不得标记为主源原文 |

源没有题目、测试或在线交互时写 `无/不适用`，不得编造。未知写 `未知/待核验`，不得省略。

## 新切片写入合同

1. 读取现有停止位置与下一 locator，核验本次 verified 来源包。
2. 在“来源与定位”写本块在任务中的位置和应掌握地图。应掌握地图是目标，不是掌握结论。
3. 在“已覆盖切片”按源顺序新增一行：切片、源内容单元、标题、要点、源内交互。切片编号保持 `<块序号>-<片序号>`，仅作为快照内部顺序，不要求来源本身使用 block。
4. 在“结构化知识点”建立 `### 切片 <编号>：<标题>`，每个新写或实质重写的切片依次包含：
   - `主源内容`：忠实覆盖的源要点与顺序；
   - `机制`：涉及的状态、对象或过程；
   - `底层规则`：控制执行/数据流的规则；
   - `应用例子`：对应且可执行的例子/操作与预期结果；
   - `边界/错误`：失效、变化或错误条件；
   - `记忆与理解`：分开写应记的语法/API 与应懂的因果规则；
   - `源内核验`：源有则记录真实锚点，源无则写 `无/不适用`。
5. 一个连续来源块结束时补充 `### 块级总结`，只收敛上方内容，不引入新课程。
6. 更新岗位/面试映射、停止位置、下一 locator 和遗留项；不写学习时长、日期计划或完成/掌握结论。
7. 运行 `scripts/validate-snapshot.ps1 -Snapshot <path>` 并修复结构问题；另做来源覆盖复核，因为校验器不判断语义真实性。

历史切片在未重新取得源正文前可以保留上一版已验证布局，避免为格式迁移伪造“重新核验”。一旦某个历史切片被实质重写，就必须使用当前合同。

## 来源标签

需要区分来源和补充时使用：`[主源原文]`、`[源内例子]`、`[源内核验锚点]`、`[官方核验补充]`、`[理解补充]`、`[应用映射]`、`[推迟]`。不要把 Agent 补充标成原文。

## 复习路由

显式进入 review 时，可先从已覆盖切片定位源范围，再从结构化知识点选择机制。快照内容本身不证明用户做过练习，也不能据此自动生成或推进复习队列。

## 讲解续接与资料断点分离

本快照的停止位置和下一 locator 只描述资料生成边界，不能用于推断实际讲解位置。`study-session-protocol.md` 管理 `25-资源区/学习快照/.study-state/<任务包ID>.json` 轻量运行状态，记录切片、机制、待补问题和下一动作，不属于用户学习证据。继续、跳过或指定位置不要求 FCC 完成、代码运行或闭环产物。源内交互字段只为兼容材料格式保留，无需向用户收集完成证明或在普通讲解中展示。讲解内容不足时按协议补足核心因果；不因字段齐全就认定充分。
