# 技术学习主线总览

> 本目录是学习主线：`00-总览.md`（本文件，路线原则与当前定位）、`10-阶段/`（各阶段任务包表）、`20-来源声明.md`（机器可读来源声明）、`岗位分析/`（面向岗位的分析）。脚本只聚合 `00-总览.md`、`20-来源声明.md` 与 `10-阶段/*.md`；`岗位分析/` 不参与机读。

## 使用方式

- 每个单元就是一个任务包，`current_unit` 是当前任务包 ID；任务包而不是自然日、ISO 周、课程章节或一次会话构成推进单位。
- 第一遍采用任务驱动、广度优先和框架优先：先形成大概与相互关系，再对当前任务需要的部分补到可用深度。
- 普通学习以课程、官方文档、示例和引导项目为输入，不自动插入复习、Quiz、模拟面试或独立验收。
- 一个任务包可以跨多个日期，一天也可以推进多个任务包；周/日日志只记录事实。
- 用户可以随时停止、交接、继续或跳过；覆盖与产物列描述可选应用目标，不要求提交产物或完成证明。
- 计划、课程完成和模型生成的材料都不证明能力；只有实际运行、观察、解释、修正或独立完成的结果才进入事实与能力证据。
- 系统不在日/周层面做计划；唯一的计划单位是学习切片。

## 权威来源

- 正式来源名称、URL 和版本边界统一登记在插件 `references/curriculum-sources.md`；本主线只维护顺序、依赖和来源代码。
- 每个任务包只选一个**主学习源**，按“用户明确指定材料 > 可公开访问的线上教程 > 官方说明文档 > 用户实际持有或提供的实体教材（精确到版次与章节）> 明确标记的 Agent 兜底讲解”选择。来源列必须以机器可解析的 `主源: CODE` 开头。
- 主学习源最多配一个**缺口补充源**，只补当前任务已经确认的缺口。
- 技术结论冲突时，以语言、数据库、库或产品的当前官方文档为准。岗位需求汇总决定优先级，不裁决 API 行为、能力状态或市场占比。

## 单元结构

| 字段 | 含义 |
|---|---|
| 单元 | 可稳定引用、执行和重排的任务包，不等同于一天、一周、课程章节或一次会话 |
| 前置 | 理解该任务通常需要的最低知识；只有真实阻塞才需要先补齐 |
| 底层逻辑 | 必须讲清的业务状态、数据粒度、口径、关系、控制流、数据流或失败机制 |
| 覆盖与产物 | 面试或任务中需要覆盖的边界，以及可运行、保存、核对或讲述的输出 |
| 来源 | 以 `主源: CODE` 声明唯一主学习源；最多一个 `缺口: CODE`；均使用已登记来源码 |

- 用户可以随时改变路线、跳过、并行或提前进入；阶段、日期日志或缺少掌握证据不能否决用户的明确选择。
- 阶段、单元或定位变化时，必须同时更新本文件与 `00-首页.md` 的路由镜像。
- 新增或重排阶段时，新建或更新 `10-阶段/` 下的阶段文件，并在 `20-来源声明.md` 增删对应声明。
