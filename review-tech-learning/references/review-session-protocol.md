# Review and assessment session protocol

Use this reference only for an explicit practice, review, or assessment request handled by `review-tech-learning`.

## Purpose

Create a coherent practice and verification surface. Preserve learner-owned work and distinguish attempts, hints, corrections, outputs, and unverified claims.

## Session shape

1. Resolve the explicitly selected task package, topic, review bank, or queue target.
2. State the tested boundary and the observable completion conditions.
3. Group two to four tightly related checks when they form one coherent task.
4. Prefer causal prediction, fault localization, changed-context transfer, and later retention over recall-only questions.
5. Leave the prediction, critical implementation or correction, and transfer decision to the learner.
6. Supply executable assertions or exact observable checks.
7. Request one consolidated result report containing attempts, commands/cells, output or failure, hints used, corrections, and unresolved confusion.

Do not reveal solutions before an attempt unless the user asks. When blocked, give progressive hints: identify the layer, name the controlling rule, narrow the state difference, then show the minimum correction.

When using an `atomic-mirror` bank, test its `primary_atomic` question directly before adding any optional transfer surface. When using an extra bank, state its declared `review_kind` and related atomics/task units. Never treat generated review-bank content as an actual learner response.

## Corrective explanation

After an attempt, explain only the mechanism needed to interpret or correct it. Do not expand the session into a new curriculum block. Hand substantial new teaching to `study-tech-learning` and a focused technical blocker to `answer-tech-learning`.

## Evidence boundary

A generated question, expected answer, assertion, date, or queue entry is not evidence. `review-tech-learning` never writes Vault facts or updates the queue; hand actual results to `record-tech-learning`.

## Mode boundary

Run this protocol only when the user explicitly chooses practice, review, or assessment. Do not activate it because an item is due, a study session or task-package step ended, an artifact exists, or capability evidence is missing. Review cannot establish task-package progress or completion.
